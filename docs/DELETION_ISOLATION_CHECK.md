# 删除隔离检查（2026-11-01）

本轮在本地隔离 SQLite、临时地图文件和浏览器测试环境中验证，未连接机器人、未删除现有业务数据，未部署 021。测试覆盖主要地图/路线资源删除链，不代表全系统所有数据类型均已穷举。

## 删除的规则

| 对象 | 允许的影响 | 必须保留/保护 |
| --- | --- | --- |
| 一条路线 | 从当前地图草稿移除该路线 | 两端站点、其他路线 UID 与属性、其他地图、已发布版本 |
| 一个站点 | 确认后移除该站点和它的相连路线 | 不相连的路线、其他站点、其他地图；任务引用或必要连通性受破坏时拒绝 |
| 一张路线地图 | 无关联时软删除，并释放显示名称供重建 | 其他路线地图、源 PGM/PCD、历史版本；有关联机器人、任务、任务链记录时拒绝 |
| 一个任务链模板 | 无活动执行时仅删除所选模板 | 其他模板、地图、路线和历史执行快照 |
| 旧版 PGM 源地图 | 无引用且目录唯一、无子地图时移至隐藏归档目录 | 有路线地图/旧版路线/作业定位引用时拒绝；重名目录、链接越界、包含子地图时拒绝 |

删除连接线后可能留下孤立站点。允许继续编辑草稿，但会提前提示“重新连接或清理孤立站点后才能发布”；发布校验不会把坏草稿替换到已发布版本。该状态不能描述成“整个系统路线被删除”。

任务依赖检查在删除预览和实际保存时分别执行。预览后若出现新任务，保存仍可拒绝，防止绕过预检。未收到成功回执时，主工作台恢复本地文档、撤销历史与选择，并要求刷新核对服务器；网络超时不能直接断言服务器没有写入。

源地图归档位置：`MAPS_DIR/.deleted-map-assets/<原目录名>-<唯一标识>`。目录内容保持，正常 PGM/PCD 和定位地图列表不展示归档。当前没有网页恢复入口，维护人员恢复前需核对同名冲突及引用关系；不要自动覆盖现有目录。

## 已执行的回归

`backend/test_deletion_isolation.py` 覆盖：

- 删除一条非必要边后，保留路线仍可发布、校验任务链并创建新任务模板，旧发布快照不变。
- 删除站点仅移除相连边；另一张同名点位地图保持不变并仍可发布。
- 必要路线的删除预览、实际写入均拒绝，拒绝后草稿和版本号不变。
- 路网断开提前提示、阻止坏草稿发布，已有发布路线仍可规划。
- 删除地图后另一张地图不变，原名称可以创建新地图且 ID 不复用。
- 删除一个任务模板后，另一个模板和地图保持可用。
- 旧版 PGM 删除要求登录权限并阻止共享资产删除；拒绝父目录带走子地图；拒绝随机选择同名目录。
- 独立源地图归档后字节保留，其他源地图可见；归档中的 PCD 不进入定位列表。

`backend/test_map_resources.py` 额外覆盖同名站点连续删除重建三次、UID 不复用、历史快照保留、过期修订和跨地图 UID 拒绝。

`frontend/test/industrial-workflow.test.cjs` 覆盖删除被拒后恢复整份本地文档、历史、原选择与批选路线，以及等待保存回执期间的重复提交/离开保护。实际浏览器已验证位置锁、X/Y/角度应用、默认/批量速度保存、删除一段后其他对象保留。
