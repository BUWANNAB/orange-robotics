# 功能缺口与验收边界（2026-11-01）

依据当前代码和交付说明核查；十个管理模块已有基础链路，不代表原提示词包的每个扩展项均完成。

## 本次补齐

定位页面支持地图拖拽初始位姿：选择有底图的地图 → 拖拽重定位 → 按下选位置、拖出朝向 → 松开预览 → 点击右侧重定位按钮并确认。紫色箭头是待提交位置，松开不发送 ROS 指令。支持取消、Esc、手工修正坐标；短拖动拒绝产生朝向。地图工作台内嵌定位页面同步生效。仿真可预览但不可下发。

主工作台新增站点先显示待确认预览，确认后才加入草稿并进入自动保存；取消、Esc 或切换工具会丢弃预览，确认后返回选择模式。单段路径速度已明确显示为目标线速度（m/s）。

### 第 6 项的当前边界

- 主工作台切换作业地图会调用 `/api/localization/activate`；只有地图身份一致、新鲜 ROS 位姿通过确认后，才显示机器人定位正常。资源列表浏览不改变作业地图。
- 自动找位复用已有全局候选搜索、地图加载、initialpose 与 NDT 新帧验证，要求定位服务、雷达、PLC 连接与新鲜导航/里程计停车反馈满足条件；无法确认时明确等待或提示辅助定位。
- 后端将作业地图身份及验证车位原子写入 `RCS_DATA_DIR/localization-recovery.json`，包括 PCD 指纹、地图发布版本、二维地图资产版本和坐标系。服务启动等依赖就绪后恢复一次；局部验证失败转全局搜索，搜索失败不无限重试。
- 刷新网页读取实时状态，不重复发送初始位姿。恢复成功不会自动恢复任务或解除停止锁。仅支持单 worker，跨进程控制仍不是已支持的部署方式。
- 上次车位只能作为同一地图、同一坐标系内的搜索初值；旧车位、地图原点或旧地图坐标不能直接视为当前定位结果。

### 第 6 项的目标流程与验收

1. 主界面清楚显示当前作业地图与定位状态。切换作业地图后，在停车条件满足时自动加载与该地图一致的 PCD、PGM/路线坐标关系；查看其他地图不隐式改变机器人当前定位。
2. 网页刷新仅重连状态，不重复发送 initialpose，不中断仍然有效的定位。
3. 持久保存已验证的地图标识、版本/内容指纹、坐标系、最近有效位姿、时间及质量。服务或设备重启后，先以同图历史位姿作局部匹配初值，收到当前雷达新帧并通过质量检查后才显示定位正常。
4. 历史初值不可用、车辆被搬动或局部匹配失败时，自动进入已有全局搜索，再由 NDT 精定位接管。跨地图禁止直接沿用旧地图的 x/y/yaw。
5. 搜索期间主界面显示“加载地图 / 寻找位置 / 精确匹配 / 定位正常”及可取消操作。错误地图、相似货架/走廊歧义、超时或断流时明确失败，仅在无法自动确定时提示人工点选大致位置和方向。
6. 定位恢复与任务继续分别处理；自动找位成功后不自动恢复车辆行驶。
7. 验收覆盖：同图网页刷新、后端重启、设备重启、车辆被搬动、不同坐标系切图、选错地图、重复场景歧义、搜索取消/断流及旧请求晚到。自动搜索已有代码仍需真实雷达成功率与误定位拒绝验证。

现有算法和现场验证边界见 [AUTO_LOCALIZATION_MOTION_CHECK.md](AUTO_LOCALIZATION_MOTION_CHECK.md)。
