# RCS 手册流程复现

本地地图工作台以《RCS 实施操作手册》的主界面为主流程：地图、站点、路线、任务链和执行状态集中显示；调度等运营页从左侧功能栏进入。

## 地图到任务

1. 在地图工作台开始雷达建图，查看实时点云/栅格状态并保存建图结果。
2. 选择已生成的点云，擦除动态噪点、裁切范围、设定可选坐标原点和方向，生成栅格地图；PGM 编辑器可修改通行区域。
3. 在主画布添加站点、连接路线、设置路线方向与区域，保存草稿、校验后发布版本。
4. 在同一工作界面查看定位状态。手动设定机器人位姿或提交 ROS 自动重定位后，再检查定位质量。
5. 新建任务链：拖入“移动到站点”，按顺序选择可达站点，设置到站等待、优先级与重复次数；可保存为模板后再执行。
6. 任务模式决定新任务链如何推进：
   - **手动**：每段导航都要操作员确认后下发。
   - **自动**：依次执行全部站点动作，并按循环次数重复。
   - **调度**：到设定时间后，连续执行任务链。
7. 任务步骤通过现有任务调度器发送给机器人；只有收到设备回执才推进步骤。失败、超时或地图发布版本变化时停止任务链并显示原因。

## 任务链约束

- 地图必须有已发布版本；每一步必须存在对应的有向路线。双向路线可反向执行。
- 重复次数支持 1—1000；`-1` 表示无限循环。重复执行必须闭环，即最后一个目标站点回到起点。
- 任务链保存发布版本快照。执行期间发布地图版本变化后，任务链会停止并要求使用新版本重新创建。
- **叉取、托盘识别和货叉升降暂未加入任务链**，后续接入真实设备协议时再实现。
- 顶部“手动/自动/调度”是 RCS 任务链推进策略；它不会切换车辆控制器的实体手动/自动驾驶模式。当前本机 ROS 适配器没有已验证的车辆驾驶模式切换协议。
- 不提供网页键盘底盘遥控，也不更改操作系统防火墙设置。底盘移动仍由既有、带定位和停止锁检查的 ROS 导航接口执行。

## 数据升级

- SQLite 开发环境启动时会自动创建新增表。
- 已有 MySQL 部署需先备份，再人工执行 `backend/migrations/002_mission_chains_up.sql`。
- 全新空 MySQL 由 `scripts/init_fresh_db.py --init-empty` 按模型创建全部表。
- `002_mission_chains_down.sql` 会删除所有任务链模板和执行历史，只能在明确回退且已备份时运行。
