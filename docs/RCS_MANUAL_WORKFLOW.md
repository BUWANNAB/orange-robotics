# RCS 手册流程复现

本地地图工作台以《RCS 实施操作手册》的主界面为主流程：地图、站点、路线、任务链和执行状态集中显示；调度等运营页从左侧功能栏进入。

## 地图到任务

1. 在地图工作台开始雷达建图，查看实时点云/栅格状态并保存建图结果。
2. 选择已生成的点云，擦除动态噪点、裁切范围、设定可选坐标原点和方向，生成栅格地图；PGM 编辑器可修改通行区域。
3. 在主画布添加站点、连接路线、设置路线方向与区域，保存草稿、校验后发布版本。
4. 在同一工作界面查看定位状态。手动设定机器人位姿或提交 ROS 自动重定位后，再检查定位质量。
5. 新建任务链：点击或拖入“移动到站点”，按顺序选择目的站，设置到站等待、优先级与重复次数；可保存为模板后再执行。目的站可经过多个中间站到达，无需把路过站逐个加入任务链。
6. 任务模式决定新任务链如何推进：
   - **手动**：每段导航都要操作员确认后下发。
   - **自动**：依次执行全部站点动作，并按循环次数重复。
   - **调度**：到设定时间后，连续执行任务链。
7. 任务步骤通过现有任务调度器发送给机器人；只有收到设备回执才推进步骤。失败、超时或地图发布版本变化时停止任务链并显示原因。
8. 左侧选择任务链，右侧“任务执行”显示轮次、当前目标和操作按钮。“本段到站后暂停”会等待当前导航段完成；“继续任务链”从尚未完成的下一步开始。当前停车使用“停止并锁定”。

## 任务链约束

- 地图必须有已发布版本；每一步必须通过有向路线网络可达。双向路线可反向执行，单向路线不能逆行。单次导航也执行相同的可达性检查。
- 普通站点地图可直接发布，无需预先放置充电站；单向路线无需强行补成往返路线。越界、孤立站点和穿越禁行区的路线仍会阻止发布。
- 重复次数支持 1—1000；`-1` 表示无限循环。重复执行必须闭环，即最后一个目标站点回到起点。
- 任务链保存发布版本快照。执行期间发布地图版本变化后，任务链会停止并要求使用新版本重新创建。
- 第一段导航实际下发后，机器人持续由这条任务链占用；到站等待、手动等待和暂停期间不会被其他任务、回充或升级插队。结束或取消后释放占用。尚未下发第一段时仍允许加载地图。
- 每一步的到站等待均有效，包括最后一个站点；末站等待结束后才显示成功。
- 执行确认使用弹窗中显示的模式；若其他操作员已改变模式，必须重新打开确认窗口。
- 主界面时间轴保留最近 500 条事件；各导航段的任务历史单独保存，避免无限循环使单条执行记录持续膨胀。
- **叉取、托盘识别和货叉升降暂未加入任务链**，后续接入真实设备协议时再实现。
- 顶部“手动/自动/调度”是 RCS 任务链推进策略；它不会切换车辆控制器的实体手动/自动驾驶模式。当前本机 ROS 适配器没有已验证的车辆驾驶模式切换协议。
- 不提供网页键盘底盘遥控，也不更改操作系统防火墙设置。底盘移动仍由既有、带定位和停止锁检查的 ROS 导航接口执行。

## 数据升级

- SQLite 开发环境启动时会自动创建新增表。
- 已有 MySQL 部署需先备份，再人工执行 `backend/migrations/002_mission_chains_up.sql`。
- 全新空 MySQL 由 `scripts/init_fresh_db.py --init-empty` 按模型创建全部表。
- `002_mission_chains_down.sql` 会删除所有任务链模板和执行历史，只能在明确回退且已备份时运行。

## 本机回归检查

使用临时 SQLite、临时地图目录和设备回执接口验证，不连接任何机器人或生产数据库：

- 后端：`python -m unittest test_missions -q`、`python -m unittest test_operations -q`、`python -m unittest test_map_workbench -q`（在 backend 目录分别运行）。
- 前端：`node --test frontend/test/*.test.cjs`（在项目根目录运行）。
- 浏览器：独立本机演示数据验证登录进入地图、PGM 显示、任务链编辑与右侧执行栏；这些结果不代表 ROS 建图、定位和底盘现场验收通过。

2026-10-27 本轮结果：任务链 12 项、运营模块 27 项、地图工作台 15 项、前端 27 项，共 81 项全部通过。浏览器已验证只保存模板不会启动任务、模板可重开编辑、模式切换有确认锁、定时任务在右侧显示计划时间。实体车辆模式切换、现场建图精度与实际导航仍需设备验收。
