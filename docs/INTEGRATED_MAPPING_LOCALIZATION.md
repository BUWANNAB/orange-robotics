# 集成建图、任务模式与刷新恢复

## 用户操作

侧栏只保留“地图与路线”工作台。工具栏点击“实时建图”，主画布显示二维预览，右侧自动提供地图名称（可修改），完成现场手推确认后开始。

1. 确认底盘处于厂家允许的安全手动/自由轮状态，定位与运动控制服务已停止，再开始采集。网页不发送行驶命令。
2. 人工推动车辆，主画布读取 ROS 增量二维栅格，约每秒更新。车体标记使用同一建图坐标系到 `base_link` 的实时 TF。
3. 保存点云后自动进入裁切/去噪/原点面板。
4. 处理完成的地图自动回到路线主画布，可继续设置路线、站点和任务。最终 PGM 在处理完成后定版；实时占用预览不等于已验证的可通行地图。

关闭建图设置只收起参数，不停止采集或预览；“返回路线画布”只退出实时预览。停止采集和保存仍保留现场确认。

## 快速手动/自动/调度

顶部明确标为“新任务”。一次点击保存新任务链的执行策略；取得服务器成功结果后才更新选中状态。此项设置不会立即启动任务，因此不再要求输入确认名称。

- 初次读取完成前不显示错误默认选中，按钮暂不可用。
- 保存期间抑制重复点击；失败显示“切换未确认”，保留上次确认状态。
- 轮询开始前后的版本标记防止旧响应覆盖刚保存的模式。
- 手动表示每步人工下发，自动表示连续执行，调度表示按设定时间开始。
- 执行中的任务保持启动时策略，设备实体驾驶模式不由此设置切换。
- 任务执行、停车、删除、建图启动等关键操作继续沿用原有确认和权限检查。

## 数据与刷新

首页优先恢复 `orange.currentRouteMap`，工作台恢复上次地图资产。地图不存在时回退到可用地图。重新建立定位 WebSocket 后读取服务端当前地图切换状态、位姿与质量反馈；网页刷新不会重复发送初始位姿或地图切换命令。

不把浏览器缓存坐标恢复成实时定位。ROS 继续运行时，页面可恢复同一地图及实时定位显示；后端/ROS 重启、TF 断流或质量未通过时仍显示未知/待确认。

建图车位只有在建图活跃、栅格新鲜、`栅格 frame → base_link` TF 新鲜时显示。网络停滞时前端独立计时隐藏旧车位。栅格 PNG 与元数据使用相同序号，避免地图增长时尺寸和原点不一致。旧地图延迟下载的底图也不能覆盖新地图画布。

## ROS 自动重定位改进

保留现有 LIO-SAM 建图和 NDT 持续定位链。本轮改进全局自动重定位：粗分辨率 FPFH/RANSAC 搜索后，使用 0.30 → 0.15 → 0.10 m 点云金字塔逐层执行点到平面 ICP。多帧复核使用精层点云，保留重叠率、RMSE、倾角、高度和多候选歧义检查。

参数 `fine_voxel` 控制精层分辨率；`consistency_distance` 和 `consistency_angle` 为多帧候选允许差异，默认 0.1 m / 0.05 rad。这些参数是验收门槛，不代表实车精度。细层仍受点数上限和既有独立进程超时限制，失败保留人工重定位方式。

验证使用独立 Windows 环境中的真实 Open3D：三帧带噪声合成表面恢复已知平面变换，位置误差断言小于 0.05 m、角度误差断言小于 0.03 rad；其中一帧错位 1 m 时拒绝候选。该测试不是实车精度结论。

ROS Python 源码和参数已修改；本轮没有连接 021，也没有部署、启动或验收实车定位。现场还需要核实雷达外参、时间同步、地图质量和工控机耗时。
